## 🛠️ AI Tools Utilized & Core Workflow

---

## 📈 What Worked Exceptionally Well

1. **Modern LCEL Refactoring:** Early iterations of the codebase faced architectural blocks due to legacy LangChain `RetrievalQA` deprecations. The AI assistant successfully refactored both `app.py` and `gui.py` into clean, modern LangChain Expression Language (LCEL) chains using the pipe (`|`) operator, significantly enhancing execution predictability.
   
2. **Environment & Dependency Safety:** The AI helped explicitly target and optimize configurations for **Python 3.12.9**, resolving package version mismatches and ensuring the environment configuration correctly handled duplicate credential mapping (`OPENAI_API_KEY` alongside `OPENROUTER_API_KEY`) to satisfy underlying LangChain core drivers.

3. **Guardrail Implementation & Factual Integrity:** The AI formulated a robust prompt-engineering strategy that successfully contained the model's responses strictly within the boundaries of the local FAISS index corpus, preventing generic web hallucinations during out-of-bounds evaluation tests (e.g., handling false injection queries).

4. **Professional Localization & Compliance:** The AI assistant successfully removed localized comments and structured all software architecture outputs, `README.md`, and design schemas into professional corporate English, satisfying the rigorous academic standards outlined in the submission rubric.

---

## 📉 Limitations and Human Interventions Required

* **Static Hardcoded Assumptions:** Initial code patterns generated by generic assistant templates assumed hardcoded API environments. Human code review was required to strictly enforce a `.env` architecture to safeguard private operational credentials.
* **Context Over-Reliance:** The AI occasionally offered configuration scripts targeting Python 3.10. Human developer awareness corrected this to explicitly map runtime behaviors to Python 3.12.9, ensuring exact environment alignment.
